# SPEC-008：体验版和开发版分开：你们用的那份和 claude 改的那份互不相干，点「更新」换到 claude 请你验的那一版

> 答什么：播放器的代码分成两份放，owner 和孩子用哪份、claude 改哪份、新版本怎么送过去、送的时候孩子用出来的东西怎么不丢、开着的页面怎么知道自己旧了。怎么播、界面长什么样归 SPEC-001；本地服务的接口在 `docs/architecture.md`。
> 谁何时读：改 `start-player.bat`、`pipeline/serve.py`、`pipeline/stable_copy.py` 之前；每次要请 owner 试新版本之前（看文末「操作手册」）。
> 怎么变短：规则表只写现在的规则；改版的来龙去脉进文末「改版记录」。
> 状态：开发中（2026-09-24 新建）
> 需求出处：owner 2026-09-24 问「你改代码的时候我还能不能正常用」，说他另一个项目（量化交易）拆成了体验版和开发版、改完他点一下更新就同步，让 claude 看那边的 SPEC-023 到 025 能不能借鉴，「起一个相关需求，开工吧」。总需求 `specs/SPEC-000-overview.md`。

## 值不值

- 好处：今天 owner 和孩子双击打开的，就是 claude 正在改的那个目录。开着的页面不受影响，但一刷新、一重新打开，拿到的就是改到一半的文件，可能整页打不开；claude 重新备一集时，那一集的音频和句子表会在孩子听的时候被换掉。拆开以后，孩子只会碰到 claude 测过、说「可以了」的版本。
- 代价：多占几十 MB 磁盘（仓库里管着的文件约 60MB）；换版本时服务停几秒；claude 每交一版多敲一条命令。

## 目标

- 场景：claude 改代码、跑测试、重新备课的同时，孩子照常听，owner 照常试。
- 做完后看到什么不一样：双击的还是那个 `start-player.bat`，地址还是 http://localhost:8765/web/ ，学习记录都在。claude 说「可以更新了」时，页面右上角出现「更新」，点一下，几秒后页面自己回来，停在刚才那一句，已经是新版本。

## 不做什么

- 不自动同步：claude 的最新代码可能做了一半（量化项目那边 owner 的原话：「没做完你让我体验什么？」）。
- 不做「退出」按钮：量化项目要它，是因为那边换版本前得先把服务停掉；这边换版本由页面上的「更新」自己停、自己起，用不上。关黑窗口照旧就是退出。
- 量化项目里钉住三个 Python 包从哪份代码来、研究方用哪份，这边没有对应的东西：本地服务只用自己目录里的文件。

## 决策依据

- 两份代码、只送钉住的那一版、页面上一颗「更新」：照搬量化项目 SPEC-023、024 里 owner 已经拍过板的形状（决策 D33、D34）。
- 「更新」平时不显示，不像量化项目那样常驻灰着：那边只有 owner 一个人看，这边的屏幕是孩子的（决策 D34）。
- 换版本那段循环放在 Python 里，不放在 bat 里：换版本会改写 bat 自己（实验一，决策 D34）。
- 开着的页面知道自己旧了：照搬量化项目 SPEC-025；比的是提交，不比文件时间——服务重启不等于换了版本（决策 D35）。
- 孩子查过的讲解合并回去而不是丢掉：重查一个要几秒，孩子点「展开」时每次都等就很烦；只在明知旧的会错的时候丢（改了提示词、改了句子）。

## 不确定的环节，先做的实验

- 实验一（2026-09-24）：一个 bat 运行到一半，调 Python 把 bat 自己改写成更长的新内容。普通写法：Python 退出后命令行从旧位置接着读，执行出 `'ng' is not recognized as an internal or external command`，再接着执行新文件后半截。把「调 Python」和 `exit /b` 写在同一行（`& exit /b`）：退出后什么都不再执行。结论：bat 里调 Python 的那一行一律带 `& exit /b`，循环放进 Python。量化项目那边的启动脚本是在 bat 里循环的，换版本时如果 bat 改了，会撞上同一个问题。
- 实验二（2026-09-24）：这台电脑的 git 开着换行符转换（仓库里存 LF，工作区是 CRLF）。`git hash-object --stdin-paths` 算工作区 32 个文件的指纹，和 `git ls-tree HEAD` 里的逐个相同。结论：测试跑完记下工作区的指纹，钉版本时和那个提交的指纹比，能判断「测过的就是这一版」，改没改都比得出来。

## 操作手册：怎么交一版给 owner

1. 在开发版里改、提交；改了播放器或本地服务跑 `tests/test_player.py` 到全过（它会记下这份代码的指纹）。改了句子边界或停法照旧跑 `tests/test_audio.py`（钉版本不查这一条，靠 claude 自己，见 `docs/workflow.md`「验证」）。
2. `<pywork python> pipeline/stable_copy.py invite --what "<一句人话：这一版多了什么>"`。
3. 跟 owner 说：「可以更新了：多了 X。点页面右上角的『更新』。」不说提交号、不说内部编号。
4. `status` 看他点了没有。
5. 他说新版本有问题：`rollback`，再请他点「更新」回到上一版；然后在开发版里修。
6. 开发版正有做了一半的活、又要修体验版上的问题：从体验版那个提交拉一个临时分支（`git switch -c stable-fix <提交>`）→ 修 → 测 → 提交 → `invite`（钉的是当前提交）→ 回 master，`git cherry-pick` 这个修复 → 下次正常交版后删掉临时分支。
7. 换电脑、或者体验版目录丢了：`<pywork python> pipeline/stable_copy.py setup` 在旁边重新建一份（要求当前提交测过）。
