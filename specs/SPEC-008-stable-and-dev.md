# SPEC-008：体验版、开发版、正式版：一套代码住在三个地方，owner 的「更新」按钮把它挪到最新

> 答什么：代码分三个地方放——claude 改哪份、owner 在哪份上试、家长和孩子用哪份；新版本怎么送到 owner 眼前、送的时候他用出来的东西怎么不丢、开着的页面怎么知道自己旧了；上线发的是哪一版。怎么播、界面长什么样归 SPEC-001；网站本身归 SPEC-009；接口在 `docs/architecture.md`。
> 谁何时读：改 `start-trial.bat`、`pipeline/serve.py`、`pipeline/stable_copy.py` 之前；每次要请 owner 试新版本之前（看文末「操作手册」）；每次部署之前（`docs/deploy-listen-app.md` 发的是体验版那一版）。
> 怎么变短：规则表只写现在的规则；改版的来龙去脉进文末「改版记录」。
> 状态：v2（2026-11-02 体验版换成网站，决策 D55）
> 需求出处：owner 2026-09-24 问「你改代码的时候我还能不能正常用」，起了单机播放器的体验版（v1，照量化项目 SPEC-023 到 025）；2026-11-02 owner 拍板三个地方一套代码（D55）：「我在用体验版的时候你同时在开发，你开发不能影响我使用；平时灰显，你开发完点亮，我一点更新就跟开发版对齐；这个时候再上线，三个全对齐」。总需求 `specs/SPEC-000-overview.md`。

## 值不值

- 好处：owner 测新版本的网站原来直接跑开发版目录（`start-hosted.bat` 时代的毛病）——claude 改到一半、owner 一刷新拿到的就是半成品。拆开以后，owner 只会碰到 claude 测过、说「可以了」的版本；线上只会出现他在体验版上验过、说「上」的那一版。
- 代价：多占一百多 MB 磁盘（worktree 里是仓库管着的文件）；换版本时服务停几秒；claude 每交一版多敲一条命令、部署多一步（发体验版那一版，不是最新）。

## 目标

- 场景：claude 改代码、跑测试、重新备课的同时，owner 在体验版上照常测，家长和孩子在线上照常听。
- 做完后看到什么不一样：owner 双击 `start-trial.bat`，打开 http://localhost:8790/ ——和线上同一个网站（访客直接听、能登录能上传），账号和材料是他自己的。页面右上角有一颗「更新」：平时灰着；claude 说「可以更新了」时亮起来，点一下，几秒后页面自己回来，停在刚才那一句，已经是新版本。

## 不做什么

- 不自动同步：claude 的最新代码可能做了一半（量化项目那边 owner 的原话：「没做完你让我体验什么？」）。
- 不做「退出」按钮：换版本由页面上的「更新」自己停、自己起，用不上。关黑窗口照旧就是退出。
- 体验版的数据不往线上搬：owner 在体验版上传的材料、注册的账号只在本机，线上是另一套（SPEC-009 的服务器数据）。
- 不做第二套代码：三个地方是同一套代码的三个停留点（D55），不是分叉。

## 决策依据

- 三个地方、一套代码、版本对齐（D55，owner 2026-11-02）：「正式版刚更新的时候跟体验版是一个版本号；我点完更新，体验版和开发版对齐；这个时候再上线，三个全对齐」。两套代码会越走越远，同一个修复要改两遍。
- 「更新」常驻灰显（D55）：体验版屏幕上只有 owner 一个人，灰着的按钮告诉他「现在就是最新的」；v1 平时不显示是因为屏幕是孩子的（决策 D34）。
- 体验版从单机播放器换成网站（D55）：owner 要测的就是要上线的那个东西；播放器的本地模式留给 claude 和 `tests/test_player.py`。
- 体验版的公共课就是仓库的 `lessons/`：线上公共库（`server-data/shared/lessons/`）和仓库里那四集现在是同一批文件的两份拷贝；体验版直接用仓库那份，课随版本走，少一处要同步的地方（正式版发布时再按部署手册铺公共库）。
- 只换到钉住的那一版、页面上一颗「更新」、失败退回、开着的页面知道自己旧了：照搬量化项目 SPEC-023、024、025 里 owner 已经拍过板的形状（决策 D33 到 D35）。
- 换版本那段循环放在 Python 里，不放在 bat 里：换版本会改写 bat 自己（实验一，决策 D34）。
- 查过的讲解合并回去而不是丢掉：重查一个要几秒，点「展开」每次都等就很烦；只在明知旧的会错的时候丢（改了提示词、改了句子）。

## 不确定的环节，先做的实验

- 实验一（2026-09-24）：一个 bat 运行到一半，调 Python 把 bat 自己改写成更长的新内容。普通写法：Python 退出后命令行从旧位置接着读，执行出 `'ng' is not recognized as an internal or external command`，再接着执行新文件后半截。把「调 Python」和 `exit /b` 写在同一行（`& exit /b`）：退出后什么都不再执行。结论：bat 里调 Python 的那一行一律带 `& exit /b`，循环放进 Python。
- 实验二（2026-09-24）：这台电脑的 git 开着换行符转换（仓库里存 LF，工作区是 CRLF）。`git hash-object --stdin-paths` 算工作区 32 个文件的指纹，和 `git ls-tree HEAD` 里的逐个相同。结论：测试跑完记下工作区的指纹，钉版本时和那个提交的指纹比，能判断「测过的就是这一版」。

## 操作手册：怎么交一版给 owner

1. 在开发版里改、提交；改了播放器、本地服务、网页跑 `tests/test_player.py` 到全过，改了网站（对外模式、library.js、login.html）跑 `tests/test_hosted_frontend.py` 到全过——两份各自记下这份代码的指纹，钉版本两边都要（R4）。改了句子边界或停法照旧跑 `tests/test_audio.py`（钉版本不查这一条，靠 claude 自己，见 `docs/workflow.md`「验证」）。
2. `<pywork python> pipeline/stable_copy.py invite --what "<一句人话：这一版多了什么>"`。
3. 跟 owner 说：「可以更新了：多了 X。体验版页面右上角的『更新』亮了，点一下。」不说提交号、不说内部编号。
4. `status` 看他点了没有。
5. 他说新版本有问题：`rollback`，再请他点「更新」回到上一版；然后在开发版里修。
6. 开发版正有做了一半的活、又要修体验版上的问题：从体验版那个提交拉一个临时分支（`git switch -c stable-fix <提交>`）→ 修 → 测 → 提交 → `invite`（钉的是当前提交）→ 回 master，`git cherry-pick` 这个修复 → 下次正常交版后删掉临时分支。
7. owner 验完说「上」：照 `docs/deploy-listen-app.md` 部署——发的是体验版当前停的那一版（R12），不是开发版最新的。
8. 换电脑、或者体验版目录丢了：`<pywork python> pipeline/stable_copy.py setup` 在旁边重新建一份（要求两份测试全过）。密钥换了：改开发版根目录的 `api-keys.txt`，双击体验版的 `start-trial.bat`，起服务前自己会拷过去。
