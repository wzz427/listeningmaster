# SPEC-012：语义切割引擎 v1

> 答什么：切割的六道工序怎么收进一个包、一条命令怎么跑、跑完怎么自己查自己（质量报告）、改了引擎代码怎么保证不退步（金样考卷）。
> 谁何时读：改 `pipeline/slicing/` 里任何代码之前（必过文末考卷）；只想重跑切割不想重备课 时；考卷红了想知道哪条规则被碰了时。
> 怎么变短：怎么切得准住 SPEC-003（识别对齐）、SPEC-004（句子边界）——本规格只管打包、命令、报告、版本、考卷，算法一行不重述。
> 状态：v1 落地中（2026-11-03 动工；五条验收是 owner 当天拍板的）。
> 需求出处：owner 2026-11-03 拍板「先做引擎化，随后无讲稿消融实验」；总需求 `specs/SPEC-000-overview.md`。

## 值不值

- 以前：六步散在 `pipeline/` 根上，只有 serve.py 按文件名点名串起来；改了边界代码，只能靠人耳抽查才知道有没有退步。
- 引擎化后：一条命令、一份自查报告、一份必过的考卷。以后做 v2（句首宁可多留、双模型会审）和材料谱系摸底，都在这个包里改，改坏了考卷会红。

## 目标

- 拿到一课的材料，一条命令跑完切割整条链，出时间轴和一页质量报告。
- 改 `pipeline/slicing/` 的代码，合入前必过金样考卷（`tests/test_slicing.py`）：四课的切割结果和仓库里的标准答案逐句一致，退步就红。

## 不做什么

- 不改任何切割算法：参数、阈值、工序顺序全不动（本规格是搬家，不是调刀）。
- 不把 `teach.py` 收进来：内容生成不是切割；备课＝引擎一条命令＋teach.py（SPEC-002）。
- 不合并六步成一个程序：每步照旧落中间文件、能单独重跑（SPEC-002「决策依据」定的结构）。

## 包结构

`pipeline/slicing/`（前七个 2026-11-03 从 pipeline/ 根原样搬进来，同名）：

| 文件 | 来路 | 干什么 |
|---|---|---|
| `audio.py` | 搬入 | mp3 → m4a（播放器）、16k wav |
| `asr_probe.py` | 搬入 | 上传、百炼录音文件识别，存 `asr_raw.json` |
| `transcript.py` | 搬入 | 讲稿 PDF／TXT →「谁说了什么」 |
| `align.py` | 搬入 | 识别对齐讲稿、切句，写 `timeline.json`（SPEC-003） |
| `refine_bounds.py` | 搬入 | 按音量精修起止（SPEC-004） |
| `ear.py` | 搬入 | 机器耳朵：一段声音听出哪些词 |
| `ear_bounds.py` | 搬入 | 机器耳朵复查边界、照人耳确认的改（SPEC-004） |
| `version.py` | 新增 | `ENGINE_VERSION`，全仓唯一版本出处 |
| `run.py` | 新增 | 一条命令：串六步、汇总质量报告 |
| `__init__.py` | 新增 | 空的，让 slicing 成包 |

搬家时**只许动「管线设施」，算法不许动**，白名单就这几样：

- 文件位置和 import 行（钥匙还在 `pipeline/keys.py`，耳朵和识别从那里读）。
- 每步入口收一个 `root` 参数（默认仍是仓库根）——考卷要能在临时目录里重放，不碰正式课目录。
- 入口函数把统计数返回出来（原来只打印）——质量报告要汇总，不改统计口径。
- `ear_bounds.py` 的机器耳朵缓存、`timeline.json` 的版本戳（见 R4、R7）。

## 一条命令

`<pywork python> pipeline/slicing/run.py <课>`

1. m4a 转码（`audio.py`）。
2. 识别：`lessons/<课>/asr_raw.json` 已经在就不重识别（识别要花钱，原样留着，SPEC-003）。
3. 讲稿 → 对齐 → 精修 → 机器耳朵（`ear_bounds.py`）：`ear_cache.json` 里听过的片段不重听（R7）。

出：`timeline.json`（带 `engine` 版本字段，R4）、`quality_report.md`。退出码：0 成功；10 音频；20 识别；30 其他——serve.py 备课改调这一条命令＋`teach.py`，对外报错的话不变。

## 质量报告（quality_report.md）

| 指标 | 哪来的 | 怎么读 |
|---|---|---|
| 对上率 | align：两边对上的词 ÷ 讲稿词数 | **红线 ≥ 80%**；低于先怀疑讲稿和录音不是同一版（SPEC-002 手册第 3 步） |
| 首词／末词通过率 | ear：机器耳朵听到第一个／最后一个词的句数 ÷ 正文句数 | 参照第一集 82/89、89/89（SPEC-004 R7）；低了读疑点句清单 |
| 边界挪动幅度 | refine ＋ ear：挪了几处、最远挪多少 | refine 最远不该超 0.2 秒（SPEC-004 R1）；ear 上限 0.6 秒 |
| 疑点句清单 | ear 挪到头也没听到的 ＋ 照人耳改过的 | 给人耳抽查；人耳定了的写 `bounds_manual.json`（SPEC-004 R5） |

| # | 规则 | 怎么验收 |
|---|---|---|

## 决策依据

- **缓存键用片段起止而不是音频内容哈希**：试探点全在两位小数网格上，起止就能唯一定一段；哈希要整段读音频算，考卷重放慢一截。同课里同起止＝同声音＝同答案，天然成立。
- **灵敏度自检进考卷而不是靠一次性人工验证**：门禁最怕「绿着但什么都不查」；一次性验证只能证明当天咬人，自检每次跑都证明还咬着。自检动的是 `PAD`——它是唯一只改本地计算、不动「听哪些片段」的参数（动 STEP、QUIET_DB 这类会改试探点阵，问出缓存里没有的新片段；第一版考卷就踩过这个坑，联网了）；考卷另把耳朵换成「一联网就报错」的哨兵，双保险。
- **`root` 参数化而不是在正式课目录里原地重放**：考卷不许改正式课数据；临时目录重放完即删。默认值仍是仓库根，单步手跑的用法不变。
- **teach.py 不进包**：owner 的原话是聚焦切割技术；内容生成（中文、生词、朗读）是另一门手艺，混在一起两边都提不动。
- **serve.py 改调一条命令、按退出码分类报错**：备课入口从「点名六个文件」变成「调引擎」；对家长看到的报错话一字不变。
