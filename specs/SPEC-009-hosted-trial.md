# SPEC-009：对外版——账号登录、上传材料自动备课、资料库侧边栏、发布到阿里云

> 答什么：把这个产品发布到 owner 的阿里云轻量服务器：家长用自己的邮箱账号登录、上传听力材料、几分钟自动备成课、攒自己的资料库；含资料库侧边栏和部署。不管：找回密码（人工重置）、邮箱验证邮件（邀请码把关）、学习记录跨设备同步（仍浏览器本地，第二版再说）、触屏适配（平板后补）、客户端 .EXE（D20 已降为离线选项）。
> 谁何时读：改 `pipeline/serve.py` 的对外模式、`pipeline/accounts.py`、上传和备课任务、`web/` 三件、部署上服务器之前读。
> 状态：开发中（2026-09-28 owner 说开干；同日 v2 大改：账号制、上传进第一版、服务器无默认内容——推翻 v1 的「一码通吃、课由 claude 上」）。
> 需求出处：`demand.md` 第 1 条（上传自动备课）、第 5 条；总需求 `specs/SPEC-000-overview.md`；决策 D47 到 D49。服务器与密钥的底账在 `docs/refs/阿里云配置指南.md`（密钥明文，已进 `.gitignore`，永不入库）。

## 值不值（两栏各一句）

- 好处：家长零安装拿到「上传材料 → 自动变课 → 听」的完整特色（owner 2026-09-26：这是产品的大特色）；真实使用暴露问题（「不能全靠自己想」）。
- 代价：账号＋上传＋服务器备课一起进第一版，两三个会话的量；轻量机带宽约 1Mbps ≈ 15 路同时听（顶到就迁 ECS，R9）；BBC 素材由各家自己传，靠邀请码＋noindex 守红线。

## 目标

- 要解决的场景：家长拿到 `listen-app.bayescode.com` 和一个邀请码 → 注册（邮箱＋密码）→ 登录 → 上传一集音频（讲稿可选）→ 几分钟后资料库里出现这节课 → 孩子打开学。
- 做完后用户看到什么不一样：不用装任何东西；换设备登录账号，自己的资料库跟着走；claude 改版部署后刷新即最新。

## 不做什么

- 不做邮箱验证邮件：注册即用，熟人圈靠邀请码把关（一个码，owner 发给谁谁是熟人）。
- 不做找回密码：人工重置（claude 在服务器上改，流程写操作手册）。
- 不做默认内容：**新装服务器资料库是空的**，包括 owner 自己也要手动上传（owner 2026-09-28 明确）——课上不上、上什么，全归各家自己。
- 不做多租户管理后台：不做管理员界面，运维走命令行手册。

## 资料库侧边栏设计（「听力资料管理」的第一版形态）

**布局**：播放器页左侧一个可收起的侧边栏（宽约 280px）。进站第一次自动展开，选了集自动收起，之后记住用户的选择。**展开是浮层**——从左边滑出、带半透明遮罩，不挤压主卡片（卡片不动，owner 讨厌内容跳动，D38 一脉）。左上角「☰ 资料库」按钮随时唤出，Esc 或点遮罩收起。**没登录任何材料时**：侧边栏显示引导——「上传一集材料开始」＋上传入口。

**内容**（信息按语义归组）：

- 顶部：账号的资料库（系列分组，窄听单元）——系列名＋「共 N 集」。
- 每集一行：
  - 左：进度点——没开始空心、进行中半满（记到播过的最高句）、完成实心（来自 localStorage 学习记录）；备课中的集显示转圈、失败显示重试。
  - 中：集号＋标题；
  - 右（小字、灰色）：时长 · 难度。
- 正在播的集：高亮＋小声浪图标；点击别的集 → 停当前音频、切过去停在句首待命。
- 底部：「＋ 上传材料」入口常驻（第一版就做——上传是核心功能）。

**难度的来源**：备课时人工/规则标注在课的元数据（BBC 系列自带 CEFR 参考级），不让模型瞎猜；没把握就不标。

## 决策依据（结论 + 理由 + 排除了什么）

- 账号用邮箱＋密码＋邀请码（D49）：邮箱是家长都有的东西；邀请码一个，守住「熟人、非商业、不公开」的 BBC 素材红线，比开放注册稳、比每家发码省事；先不做邮箱验证邮件和找回密码，试用版人工兜底。
- 无默认内容（owner 2026-09-28）：服务器不预放任何课，包括 owner 也手动上传——版权责任归各家自己，产品行为和「资料库是我的」心智一致。
- 上传＋服务器备课进第一版（D49，推翻 v1 的「第二版再做」）：没有内容的资料库没法试用，owner 明确要完整特色。
- 子域名 `listen-app.bayescode.com`（owner 2026-09-28 拍板，要带 `-app` 字样）；排除 `bayescode.com/apps` 路径——URL、cookie、反代规则背着前缀互相挤。
- 机器用 39.105.73.114（owner 确认）：TinkerCode 的回滚备胎＋课程官网机，有余量；排除哨兵机 47.95.122.198——「监控者不能和被监控者同生共死」（指南铁律）。
- 侧边栏浮层不挤压：owner 界面偏好（极简、讨厌跳动、控制权给用户）。

## 不确定的环节，先做的实验

- pipeline 在 Linux 服务器跑通：ffmpeg 用 imageio-ffmpeg 自带的（pip 可装）；六步程序串一条命令后先在开发机 WSL/服务器上手跑一集——动工第一步。
- serve.py 在 Linux 跑：Windows 上那个「同端口只起一个」的锁要条件化。
- 39.105.73.114 的 Caddy 现有配置怎么加块：部署时先拉回来 diff 再改（指南坑⑦）。
- localStorage 记录按域名隔离：家里 8765 的学习记录不带到服务器——提前给 owner 说明，避免误会丢数据。
