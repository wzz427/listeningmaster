# 教训 —— 哪些路别再走

> 答什么：真踩过的坑。撞到报错时搜报错字眼；开机扫最上面几条。
> 不归档、不拆分：教训没有生命周期，用法是搜。每条：症状（贴真实报错字眼）/ 根因 / 修法 / 怎么确认修好了。

## 最容易撞的

| 症状 | 一句话因 | 修法 |
|---|---|---|
| 密钥出现在对话里 | 想「遮蔽后再打印」，遮蔽规则没覆盖新格式 | 任何情况下都不打印密钥文件，读取只走 `pipeline/keys.py` |
| `conda install ffmpeg` 报 `UnicodeDecodeError('gbk'...)` 后整体回滚 | 它顺带装的图形库在中文 Windows 上跑不完安装脚本 | 改用 `pip install imageio-ffmpeg`，它自带一个独立的 ffmpeg |
| 终端里中文变成乱码 | Windows 控制台默认不是 UTF-8 | 程序入口加 `sys.stdout.reconfigure(encoding="utf-8")` |
| 矢量图标切换显示没反应 | `svg.hidden = true` 对矢量图不起作用 | 用 `toggleAttribute('hidden', ...)` |
| 挪句子边界后某句开头多出几秒音乐 | 搜索范围覆盖了两句之间的整段空隙 | 句首句末各自只在原位置附近找 |
| 点下一句没反应，音频永远从头播 | 本地服务不支持 Range，浏览器跳不过去 | 用 `pipeline/serve.py`，别用 `python -m http.server` |
| 声音不对，自动化测试全通过、自己也查不出来 | 测试只核对「浏览器报告播到第几秒」，从没听过放出来的声音；量音量只看切口安不安静，不看切下来的是什么 | 录下浏览器真正放出来的声音，交给机器耳朵听（`tests/test_audio.py`），再做试听页给人耳抽查。见下面 2026-09-22 那条 |
| 单播一个词带进前后词的碎片 | 识别给的词时间偏晚且每个词偏得不一样；按安静处切又会切在 k、t、p 中间 | 切不准，功能已删（决策 D24）。别再按识别给的词时间切单个词 |
| 机器耳朵批量听的时候，后面的全都「没听到」 | 一分钟里调得太多被限流，返回的不是识别结果，被当成了「没听到」 | `pipeline/ear.py` 失败就等一会儿重试，同时最多 4 路 |
| 让大模型分段，切得很碎（6 段、每段 40 到 70 秒） | 只告诉它「每段不超过 120 秒」，它就往细里切 | 把总时长和目标段数一起告诉它，并写「段数宁少勿多」（`pipeline/teach.py` 的 `split_sections`） |
| 在 Bash 里用 Python 脚本批量替换代码，报 `AssertionError`、要找的文字对不上；或者没报错、但替换的位置差了一个字符 | 这里的 Bash 工具就算 heredoc 的结束标记加了引号（`<<'EOF'`），也会把 `\\` 吃成 `\`：脚本里写的 `"\\n"` 到了 Python 变成换行（2026-09-22 查清，一共犯了四次，最后一次少了一个空格；查清以后又犯了一次，f-string 里的换行符变成了真的换行） | 要找的文字里有反斜杠时，一律改用 Edit 工具逐处改；按位置切片时别用含反斜杠的字符串算长度；要整段退回就 `git show <提交>:<文件>` |
| 调 deepseek-flash 一次要 1.5 秒，回答前先「想」了一两百个字 | 它默认开着思考模式 | 请求里带 `extra_body={"thinking": {"type": "disabled"}}`，一次 0.4 秒（`pipeline/llm.py` 已默认关掉，owner 要求不开） |
| 装一个包之后别的包报版本冲突（`typer requires click>=8.2.1, but you have click 8.1.8`） | 装 gTTS 时它要求旧版 click，pip 顺手把 pywork 里的 click 降级了 | 装包前先 `pip install --dry-run <包>` 看会不会降级别的包；已卸掉 gTTS、click 装回（2026-09-22）。谷歌朗读直接取，不用这个库 |
| 百炼语音合成读单词，头一个音读坏（need 读成 aid、drank 读成 rank） | 直接给小写的单个词，模型不当成一句话读 | 首字母大写再加句号（「Drank.」）能治头一个音，但语调还是怪；后来改用谷歌翻译的朗读（决策 D27），百炼合成的代码已删 |
| 机器耳朵判朗读、判句首，结果忽对忽错 | 单听一个词很容易听岔（to→two、know→no）；同一段声音换个采样率（16k 和 48k）它就一会儿听到 I'm、一会儿听不到 | 机器耳朵只用来排先后、挑可疑的，拍板靠人耳（`tts.py check`、`bounds_manual.json`） |
| 以为找到了两句之间的静音，挪了分界，owner 一听把上一句的词切掉了 | 又是 k、t、p 的坑：interesting 的 t 发音前嘴先闭住，那 0.03 秒安静得像句间空当（第 47、48 句，2026-09-22，同一个坑踩第二次） | 按音量找到的「静音」只能当候选，挪不挪由人耳定；人耳定下的写进 `lessons/<课>/bounds_manual.json`。说话人自己吞掉的音（第 5 句 I'm、第 48 句 I）怎么切都找不回来 |
| 做完了 owner 说「我什么时候说过……」 | 他的话是语音转写的长句，「我考虑还是别在备课期间全都生成简单解释，只有点击展开的时候，再生成详细的解释」可以有两种读法，我按字面挑了一种就动手，没复述给他确认（2026-09-22，单词卡那一行什么时候生成） | 管产品方向的话读着有两种意思，先用一句话复述「我理解成 A，对吗」，他点头再做 |
| 让模型从一串词里挑出生词，每次挑得差很多，还把 prefer、terrible 这类常见词算进去、漏掉 cut down on 里的 cut、down | 只给一串词，模型看不出每个词在这集里怎么用；「挑出来」的写法让它扫一眼就交差 | 每个词带上它出现的那句，要它逐个答是不是（`pipeline/teach.py` 的 `mark_hard`，2026-09-22）；三次结果基本一致，4.6 秒 |
| 网页上的音标可能东拼西凑换字体 | 网页用的 Literata、DM Mono 都没有 ə、ʊ、ˈ、ː 这些符号（2026-09-22 用 fontTools 查的），缺了浏览器就从系统里随便找一个补 | 音标专用一个 Noto Serif 裁出来的字体（`web/fonts/noto-serif-ipa-400.woff2`，34KB）；以后要显示别的特殊符号，先用 fontTools 查字体里有没有 |
| Playwright 的 `page.evaluate` 莫名其妙把桩函数调了一次 | 传进去的字符串最后一个表达式是函数（`x.speak = () => ...`），Playwright 会把它当函数调用 | 字符串末尾加 `; 0` |
| ffmpeg 切出来的一段全是静音 | 在 `-i` 后面用 `-ss` 截取时，滤镜里的时间还是原音频的时间，`afade=t=out:st=1.45` 从第 1.45 秒起全压成零 | 用 `atrim=start=..:end=..,asetpts=PTS-STARTPTS` 截取并把时间归零，再接 `afade` |
| 百炼报找不到文件或地址无效 | 录音文件转写模型只收公网地址，不收本地路径 | 用 `dashscope.utils.oss_utils.upload_file` 传到临时存储，并加请求头 `X-DashScope-OssResourceResolve: enable` |

## 全部（新的在上）

### 2026-09-22 · 单词原声 owner 两次听出不对，我两次都没发现

- 症状：点词播「这句里的原声」，owner 听到带杂音；第一次修完他再试，「还是不对」，并问「你现在检测切完的声音对不对，用的是什么方法」。
- 根因一（验证方法）：`tests/test_player.py` 只核对数字——浏览器说播到了第几秒、停在第几秒，和算好的切口对得上就算过。
  分析音量用的是 16k 的 wav，浏览器播的是 m4a，两者对不对得上、放出来的到底是什么声音，从来没验过。第一次修只量了「切口安不安静」，切口安静不等于切对了。
- 根因二（声音本身）：录下浏览器放出来的声音、交给机器耳朵一听才看清——播放器放得很准（和切口差不到 10 毫秒），错在切口：
  识别给的词时间偏晚，每个词偏得不一样（整体挪一个固定值最多对一半，换 paraformer-v2 也只有七成）；
  k、t、p 发音前嘴先闭住，那一下很安静，按安静处切就把前一个词的爆破音切到了后一个词头上（点 each 听到 Chub）。
- 修法：单词原声拿掉（决策 D24）。验声音改成三层：录下真的 Chrome 放出来的声音 → 和原音频逐个采样比对，算出实际放的是哪一秒到哪一秒 → 交给机器耳朵听是不是那几个词；最后做试听页给人耳抽查（`tests/test_audio.py`）。
- 怎么确认修好了：同一套方法顺带查出约 9 句开头被切掉，加了 `pipeline/ear_bounds.py` 之后，开头对得上的从 77 升到 83 句（共 89 句），结尾 89 句全对。
- 连带教训：机器耳朵也会骗人。它很宽容（-ugar 也听成 Sugar），有自己的毛病（I've 听成 I），被限流时返回的不是结果。它能挑出明显的错，拍板还得靠人耳。

### 2026-09-21 · 挪句子边界把第 1 句的开头挪前了 5 秒

- 症状：精修边界后，第 1 句 Hi, Neil. 的开头从 20.96 秒变成 15.65 秒，点第 1 句先放 5 秒片头音乐。
- 根因：搜索范围写成「从本句末尾到下一句开头的整段空隙」，片头后有 5 秒多的空隙，挑中了空隙最前面的安静段。
- 修法：句末只在原句末前后 0.15 秒里找，句首只在原句首前后 0.15 秒里找（`pipeline/refine_bounds.py`）。
  报告里写出挪得最远的是多少，超过 0.2 秒就说明又挪错了。
- 怎么确认修好了：第 1 句回到 20.96 秒；`bounds_report.md` 里挪得最远的是句首 170 毫秒。
- 连带教训：改完先看一眼改动最大的那几个，不能只看平均值。平均值当时看着很好。

### 2026-09-21 · 播到句末会带进下一句开头的一点声音

- 症状：owner 试用时听出来的。
- 根因（量出来的，不是猜的）：识别给的时间 40 毫秒一格，句子起点系统性偏晚。97 处交界里，句末之后多播 20 毫秒就能听到声音的有 16 处；
  另外播放器是每一帧检查一次到没到句末，天生会多播十几毫秒，而且停的时候不渐弱。
- 修法：两头一起修（决策 D18）。备课时按音量挪边界，降到 12 处；播放器停之前先把音量渐弱到零。
- 怎么确认修好了：`tests/test_player.py` 的 A1a、A1b——停的位置不超过句末 30 毫秒，停的那一刻音量为零。
  「听起来干不干净」还要 owner 用耳朵验。

### 2026-09-12 · 播放器点「下一句」只能听到第一句

- 症状：点下一句、上一句、重听，音频都不动，来回只播得到第一句。页面没有任何报错。
- 根因：我用 `python -m http.server` 起的本地服务**不支持 Range 请求**（从文件中间取一段）。
  浏览器要跳到第 25 秒，必须只取那一段；服务每次都把整个文件从头给它，于是跳转失败。
  用 `curl -r 100-200` 一试就看得出来：返回的是 200 和整个文件，不是 206 和一小段。
- 修法：改用 `pipeline/serve.py`，它支持 Range，顺带关掉了缓存，改代码刷新就生效。
- 怎么确认修好了：`tests/test_player.py` 里的 A-next 用例——点下一句之后，音频的当前秒数
  落在第 2 句的起止范围内。修之前这条必然失败。
- 连带教训：光检查「文件能不能取到」不算验过。当时我只 curl 了状态码 200 就交给 owner 了，
  真正该验的是「点了之后音频播到第几秒」。

### 2026-09-12 · 密钥被打印进了对话

- 症状：为了看密钥文件的结构，用正则把密钥替换成星号后打印，结果 `sk-ws-` 开头的那把没被遮住，原文进了会话记录。
- 根因：遮蔽规则假设密钥是 `sk-` 加字母数字，新格式中间带了连字符。靠「遮蔽后打印」本身就是错的做法，遮蔽规则永远追不上新格式。
- 修法：密钥文件一律不打印、不 cat、不 grep。要用就在程序里读（`pipeline/keys.py`），要确认格式就只判断读没读到，不输出内容。
- 怎么确认修好了：`pipeline/asr_probe.py` 全程没有任何一行输出包含密钥，上传得到的地址也只打印前缀。
- 后续：owner 决定不重置这把密钥，此事不用再提。

### 2026-09-12 · conda 装 ffmpeg 失败并回滚

- 症状：`conda install -n pywork -c conda-forge ffmpeg` 跑到最后报 `An error occurred while installing package 'conda-forge::gdk-pixbuf'`，接着 `UnicodeDecodeError('gbk', ... 'illegal multibyte sequence')`，整个事务回滚，ffmpeg 没装上。
- 根因：conda-forge 的 ffmpeg 会连带装 gdk-pixbuf，它的安装后脚本输出中文报错，conda 用 GBK 解码失败。
- 修法：`pip install imageio-ffmpeg`，用 `imageio_ffmpeg.get_ffmpeg_exe()` 拿到独立的 ffmpeg 可执行文件（见 `pipeline/audio.py`）。代价是没有 ffprobe，用 `ffmpeg -i` 读信息代替。
- 怎么确认修好了：`pipeline/audio.py` 能把 mp3 转成 16kHz 单声道 wav，`probe()` 能读出时长和声道数。
