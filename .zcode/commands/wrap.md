# /wrap —— 压缩上下文之前的收尾

owner 敲这个 = 「我想压缩了，你先把该存的存好」。压缩本身不用你管：ZCode 在上下文满了的时候自动摘要，摘要会带进下一个窗口；这个命令做的是趁上下文还完整，把只活在里面的东西都落到盘上。交付 = 盘上干净 + 五句话，五分钟以内。

**做完所有需要上下文的判断，不做任何不需要上下文的执行。** 修 bug、补测试、改文档正文都是执行，写进 `docs/debts.md` 压缩之后再做。

1. **判能不能收**。有后台任务没回来 / 有改了一半没验的代码 / 正在实验中途 / 欠 owner 一个要靠上下文才答得出的答复 → 先说清在等什么，能存多少先存多少。
2. **把只活在对话里的东西写下来**（先做，不可恢复）：量出来的数 → 它该住的文档；owner 拍的板和理由 → `docs/decisions.md` 或 `CLAUDE.md`；干到一半的活 → `docs/handoff.md`「下一步从哪接」；答应他的事和等他定的问题 → `docs/handoff.md`「等 owner 亲手做的」；临时目录里还要用的东西 → 搬进仓库或写清怎么重做。只记事实，不记推断。
3. **扫文档**：`docs/debts.md` · `docs/handoff.md` · `docs/decisions.md` · `docs/lessons.md` · changelog（有的话）。纯替换当场改（改名、改路径这类），别的写进欠账表。列得出扫过哪几份才算扫了。
4. **提交**（几个会话同时干活时带文件列表）。这里不跑全套测试，只如实写上次跑测试是什么时候、结果如何。
5. **给 owner 五句话**：能不能收 · 存了什么、改了哪几份（带提交号）· 欠账表还有几条 · 有没有「要你亲手做的」· 「该保的都在盘上，可以放心压缩了」。不给他任何要粘到别处的话。

压缩之后第一个动作：读 `docs/debts.md` 和 `docs/handoff.md`，接着干主线；owner 一开口给新活就先干新活。
